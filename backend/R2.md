# 从 Cloudflare R2 读取数据

`r2_import.py` 是已有 `r2_sync.py` 的读取端。上传同步仍按原方式运行；读取端只调用 ListObjectsV2 和 GetObject，不写入或删除 R2 对象。

支持现有目录：

```text
music-scores/
  imslp/
    imslp-作品ID/
      metadata.json
      audio/录音.mp3
      scores/乐谱.pdf
```

`_source`、`_state`、目录占位符、临时文件不作为作品资料导入。每部作品可有多份音频和多份乐谱。非这个目录结构的对象会列入 inventory.json 的 skipped 清单，不按相似文件名猜测配对。

## 查看清单与选择性缓存

安装 `requirements-r2.txt` 和 `requirements-collector.txt`，Python 3.11+。从 backend 运行：

```sh
python r2_import.py list --endpoint https://ACCOUNT_ID.r2.cloudflarestorage.com --bucket music-scores --prefix imslp --root data/r2-cache
python r2_import.py pull --endpoint https://ACCOUNT_ID.r2.cloudflarestorage.com --bucket music-scores --prefix imslp --root data/r2-cache --work imslp-作品ID
```

可重复传入 `--work` 选择多部作品。不指定时 `pull` 默认选前三部同时有音频和乐谱的作品，`--limit` 可调整。只下载所选作品的媒体和 metadata.json，单对象默认上限512 MB，可用 `--max-mb` 调整。

清单保存在缓存目录 `.r2-import/inventory.json`，包含作品ID、对象键、文件大小、ETag和两种媒体是否齐备。列清单不下载媒体。`pull` 会分页重新列清单，使用 If-Match 读取列出时的对象版本，途中远端变化会记录失败，重跑即可刷新。

缓存与校验记录保存在 `.r2-import/state.json`。已缓存文件检查本地SHA-256，不重复下载未变化的文件；ETag仅用作对象版本标识，不当成MD5或SHA-256。若上传端提供了sha256元数据，下载时额外核对。字节数或哈希不匹配时不发布临时文件。文件级进度可恢复；未完成文件重新下载，不做Range字节续传。

已存在且不属于该缓存的本地文件不会被覆盖。不同R2源应使用不同缓存根目录。请将缓存放在专用目录，不与手工维护的原始资料混放。

## 接入现有工作台

启动 `start-dataset.sh` 或 `start-dataset.ps1`，在“本机数据根目录”中选择刚才的缓存根目录绝对路径，点击扫描。音频试听、PDF预览、重复内容分组及数据集划分沿用现有功能。缓存尚未覆盖整个桶时，扫描结果只包含已缓存作品。

本版按作品选择性缓存，不是浏览器直接访问整个R2桶。预览前需要先缓存所选作品；不会为列清单而全量下载。

## 凭据

进程从 `R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY` 环境变量读取凭据，随后移除环境变量。密钥不进入日志、缓存清单或Git文件，退出后需重新注入。推荐通过项目现有 secret-input 安全输入窗口传入 Secret Access Key，而不是把密钥粘贴到终端命令或聊天中。R2凭据至少需要选定桶的列举与读取能力。

连接地址、桶名和目录前缀可复用此前上传同步配置；同步进程内存中的密钥不会自动共享给新的读取进程。

## 验证

```sh
python -m unittest discover -s tests -p test_r2_import.py -v
```

测试包括分页、按作品选择、重跑跳过、远端变化、缓存损坏恢复、原文件保护、路径越界及符号链接拦截、列举后对象变化等。`pull` 退出码0表示所选对象均已下载或在缓存中，2表示部分失败；查看 `.r2-import/last-result.json` 获取失败对象及原因。

实际验证（2026-09-08）：复用已有 `music-scores` 桶、`imslp/` 前缀和R2地址；远端列出568部作品，51部同时有两类媒体。选择3部作品成功读取9个对象（3音频、3乐谱、3元数据），失败0。数据工作台扫描得到3个独立作品组，6个媒体预览接口均返回完整内容，划分预览为训练/验证/测试各1组。110项后端测试通过。缓存路径为 `backend/data/r2-cache`；测试未修改远端对象。

## 工作台云存储入口

选择“2 云存储”，填写 `https://账户.r2.cloudflarestorage.com/桶名/前缀/`，然后输入 S3 Access Key ID 和 Secret Access Key。已有清单中的连接地址会自动预填。连接后勾选作品，点击“缓存所选作品并扫描”。每批最多100部作品、每对象最大512MB。只支持 R2 S3 地址，不支持控制台链接或任意单文件分享链接。

默认勾选“记住连接”：连接验证成功后将 Access Key ID 和 Secret Access Key 存入 macOS Keychain / Windows Credential Manager / Linux Secret Service。普通配置文件 backend/data/cloud-profile.json 只保存连接地址。提交后输入框清空，不使用浏览器持久存储。重启或刷新后点击“使用已保存的连接”即可；断开不会删除保存的凭据，“删除已保存凭据”会删除凭据并断开当前会话。不勾选记住时仍只保存在进程内存中。系统凭据库不可用会报错，不回退到明文文件。云端缓存位于 backend/data/cloud-cache 下按来源区分的目录。扫描和划分针对该来源已缓存的作品，不代表整个桶，缓存失败会逐项显示。

持久保存实现使用系统凭据库接口：[keyring 官方说明](https://keyring.readthedocs.io/en/latest/)。2026-09-08 验证：116项后端测试通过；本机 macOS 钥匙串写入、另一进程读取、删除临时测试条目均通过。Windows/Linux 尚未在实际设备验证。
