# 本地音乐数据工作台

用于收集多版本录音和乐谱、检查缺失及重复文件、按作品分组、导出训练/验证/测试文件索引。本阶段不下载模型、不训练模型，不把未识谱、未对齐的资料标为训练完成。

## 启动

Windows 安装 Python 3.11 x64（带 Python Launcher），在 backend 目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dataset.ps1
```

macOS / Linux 安装 Python 3.11 或更新版本，在 backend 目录运行：

```sh
sh start-dataset.sh
```

浏览器打开 http://127.0.0.1:8766 。保持终端窗口打开。首次启动会安装轻量 API 依赖，不需要 GPU 或分轨模型，独立虚拟环境为 `.venv-dataset`。已有分轨服务的 8765 端口不受影响。

## 放文件

在界面输入数据根目录的绝对路径（例如 `D:\MusicDataset`），填写作品名称并点击创建文件夹；也可以使用自己已经整理好的目录：

```text
MusicDataset/
  Strauss_Op325/
    audio/
      Orchestra_A.mp3
      Orchestra_B.flac
    scores/
      Edition_A.pdf
      Edition_B.musicxml
  Beethoven_Op67/
    audio/
    scores/
```

一部作品一个顶层文件夹；同一作品的不同乐章、录音、出版版、改编版都放在其下的 audio / scores 目录中，可继续分子目录。目录名区分作品需要你确认；软件不会仅凭相似曲名识别同一作品。即使某个改编差异很大，保留在同一作品组也有助于避免训练/测试泄漏。

支持 MP3、WAV、FLAC、M4A、OGG、AAC、AIFF，以及 PDF、MusicXML、MXL、MIDI、MSCZ、MSCX。扫描依据扩展名，不保证文件内容合法。音频能否试听取决于浏览器解码能力；PDF 可内嵌预览，其他乐谱格式需用打谱软件查看。

扫描读取文件和计算 SHA-256，大数据集可能需要较长时间；空文件被跳过，符号链接不跟随。不要在扫描或导出期间修改文件。

## 划分规则

- 只纳入至少有一份非空录音和一份非空乐谱的作品，其余写入 excluded.jsonl。
- 同一作品的所有版本固定在同一集合。跨作品文件夹检测到相同内容时，将它们绑定成同一组，不因文件名不同而拆开。
- 不同编码、不同裁切的重复录音不会被内容哈希识别；同一作品的不同版本仍需正确归入同一个作品文件夹。
- 默认 80/10/10，以独立作品组数量计算。可修改比例和随机种子；组数较少时，保留三组非空优先于精确比例。少于三个独立组时不生成三分数据集。
- 作品组按名称排序，再使用固定随机种子打乱。相同输入及参数可复现；添加或删除作品后重新划分可能改变旧分组。
- 文件内容变化后，旧的预览不可直接导出，必须重新扫描。

## 导出

点击“预览划分”后再“导出三套清单”。结果位于数据根目录下 `.music2pdf/splits/时间-唯一编号/`，不覆盖旧结果、不移动音频和乐谱。请保留该导出目录用于固定实验版本。

每个 JSONL 文件每行代表一部作品，包含 id、group_id、audio、scores、格式、文件大小、内容哈希与相对路径；路径以 manifest.json 的 root 为基准。manifest.json 记录比例、种子、算法版本、指纹和警告。

`training_ready` 始终为 false，`label_status` 为 unverified_unaligned：这是一份数据目录清单，不是模型训练所需的精确音符标签。PDF 尚需 OMR；结构化谱也需要核对实际演奏版本、移调乐器、反复与删节，再建立时间对齐。不能将一个作品内所有音频与所有乐谱自动笛卡尔积配对，或将“有文件”当成正确监督标签。

本服务面向单用户本机使用，不配置公网认证，保持默认 127.0.0.1 监听地址。数据不会被上传。

## 测试

安装 requirements-test.txt 后，从 backend 目录运行：

```sh
python -m unittest discover -s tests -v
```

测试覆盖按作品分组、重复内容绑定、随机种子复现、非空集合、缺失文件排除、原文件保护、导出前变化检查及 HTTP 工作流。

## 自动发现 IMSLP 资料

可使用 [IMSLP 采集器](IMSLP.md) 从官方目录主动发现作品，不必手动提供链接。将采集器的 `--root` 设为本工作台的数据根目录，成功下载的文件即可直接扫描。作品来源、版本和采集状态保存在各作品目录的 metadata.json；受站点访问限制的项目仅保存元数据，不会被算作已有录音或乐谱。
