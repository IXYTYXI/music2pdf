# Cross-platform recording discovery implementation plan

> Execute inline with superpowers:executing-plans. Work in codex/recording-discovery; merge into codex/piano-transcription after tests and review, as requested by the user.

**Goal:** Find candidate recordings for existing IMSLP scores, show matching evidence and access/license information, and download explicitly selected recordings into the local dataset for R2 synchronization.

**Architecture:** Separate work identity/matching, official Archive/Commons API adapters, and a resumable CLI queue. Store external candidates in each work's `recordings/metadata.json`, never rewrite the IMSLP-owned `metadata.json`. A separate hidden SQLite queue tracks provider search outcomes and selected downloads. Records stay unverified_unaligned. Existing collection/sync processes remain running.

**Tech stack:** Python 3.11+, requests, BeautifulSoup, SQLite, unittest; reuse limited/retrying transport and audio signatures.

Completion means working feature and verified merge, not discovery of every recording on the web. MusicBrainz/Musopen/composer-site connectors and browser extraction are outside this first implementation. Search results are candidates, not an assertion that any exact score edition was performed. No login or streaming extraction is attempted.
